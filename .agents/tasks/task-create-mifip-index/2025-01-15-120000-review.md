# MiFIP single-page product calculator and brochure

An 809-line self-contained HTML page that presents Manulife Indonesia's MiFuture Income Protector insurance product as a tabbed single-page application. Five tabs cover product summary, benefits breakdown, an interactive benefit calculator, illustration simulations, and a 12-question FAQ. All CSS and JavaScript are inline with no external dependencies. The page is anchored by a sticky WhatsApp banner and a floating WA button that direct prospects to the agent's phone number.

Watch for: The calculator's 800% total double-counts the death benefit that, per the product rules, reduces the end-of-term benefit — the UI presents them as additive, which may overstate guaranteed returns (**confirmed**). The Dana Mapan input field accepts raw text but only strips non-digits, so pasting a value with a decimal or comma can silently truncate it (**confirmed**). No `<meta>` tags for social sharing or SEO beyond the title exist, which matters for a page designed to be shared via WhatsApp links (**confirmed**).

## High-level view

The calculator implements the product's benefit formula correctly at the percentage level (100% + 400% + 200% + 100% = 800%), but the presentation obscures a product-level nuance documented in the page's own footnote: the death benefit reduces the end-of-term payout, so a policyholder who claims one does not receive both in full. The total banner always shows 800% regardless.

Input handling in the calculator strips non-digit characters and validates minimums, but the default value (100,000,000) stays IDR-scale when switching to USD, immediately producing a nonsensical USD 800M total. No formatting feedback or locale-aware parsing exists.

The page misses ARIA coupling between tabs and panels (`aria-controls`/`aria-labelledby`), which means screen readers can't associate a tab with its content. No Open Graph meta tags are present, so WhatsApp link previews will show a bare URL instead of a product card.

<summary>Issues (5)</summary>

1. **800% total misrepresents mutually-exclusive benefits** — The death benefit (100%) and end-of-term benefit (200%) are not fully additive per the product footnote, but the calculator and total banner present them as such. Add a disclaimer or adjust the total to reflect the either/or nature.
2. **Dana Mapan input loses precision on paste** — Stripping non-digits from pasted values like "50.000.000" works for IDR dot-separators, but USD values with decimals (e.g. "10,000.50") silently become "1000050". Validate or format the input based on selected currency.
3. **Default value stays IDR-scale when switching to USD** — The input's initial value is 100000000. Switching to USD doesn't reset it, so the user sees a USD 100M calculation (far above realistic). Reset or adapt the default when currency changes.
4. **No Open Graph / SEO meta tags** — The page is designed to be shared via WhatsApp but lacks `og:title`, `og:description`, `og:image` tags. WhatsApp link previews will show a bare URL instead of a product card.
5. **Tab-panel ARIA coupling missing** — Tabs use `role="tab"` and panels use `role="tabpanel"` but lack `aria-controls`, `aria-labelledby`, and `aria-selected`. Screen readers cannot associate tabs with their content.

## Calculator logic and the 800% claim

The calculator computes `totalManfaat = danaMapan * 8` unconditionally. This matches the marketing headline but conflicts with the product's own footnote rendered in the Manfaat tab:

```
*Manfaat Meninggal Dunia mengurangi Manfaat Akhir Pertanggungan jika sudah dibayarkan
```

If death benefit is paid, end-of-term drops from 200% to 100%, making the actual maximum either 800% (survive to end) or 200% (death during term) — never both simultaneously to the same beneficiary. The calculator offers no toggle or disclaimer for this scenario. This risks a compliance objection from Manulife's legal review since the page itself documents the mutual exclusion in small print.

## Input handling and currency switching

The Dana Mapan input strips all non-digit characters (`replace(/[^0-9]/g, '')`), which works for whole-number IDR inputs but creates two problems:

The default value of `100000000` (100 million) makes sense for IDR but is nonsensical for USD. Switching currency to USD does not reset or adjust the input, so the calculator immediately displays "USD 800,000,000" as total benefit — a number no individual policy would reach. A `change` handler on the currency dropdown should reset the input to a sensible default (e.g., 10000 for USD).

For USD inputs that include decimals (common in international finance), stripping non-digits discards the fractional part. "5,000.50" becomes "500050". Since Dana Mapan minimums are whole numbers this won't trigger validation failures, but it silently corrupts user intent.

## Accessibility gaps

Missing ARIA pieces in the tab implementation:

- No `aria-controls="tab-ringkasan"` on each tab `<li>` linking it to its panel.
- No `aria-labelledby` on each panel pointing back to its tab.
- `aria-selected` is never set; only a CSS class `active` drives visual state.
- Keyboard navigation (arrow keys between tabs, Enter/Space to activate) is absent.

The missing ARIA attributes are trivial to add and would satisfy automated accessibility audits.

## WhatsApp sharing without Open Graph

The page is designed to be shared via WhatsApp (sticky banner, floating button, pre-filled message), but the `<head>` contains no Open Graph tags. When the page URL is pasted into a WhatsApp chat, the preview will show only the bare `<title>` text with no description or image. Adding `og:title`, `og:description`, and `og:image` would give the shared link a rich card preview — significant for conversion in a WhatsApp-first distribution model.
