# Bidirectional premium calculator with rate interpolation

The calculator tab has been replaced with a comprehensive premium computation engine. It accepts either Dana Mapan (sum assured) or Premi (premium) as input and solves for the other, supports five payment modes with exact multipliers from sample data, embeds seven known actuarial rate points with power-law interpolation for unknown age/gender combinations, applies a four-tier band factor system for premium scaling, displays all-mode premium equivalents, and preserves the existing 800% benefit breakdown downstream. The page also gains Open Graph tags, ARIA tab coupling, and currency-switch-aware defaults — fixes from the prior review pass.

Watch for: The rate interpolation model (`4.85 * gap^-0.82` for Pria) is a curve fit to seven data points with no validation against official rate tables for the ~200 unseen age/gender/UM combinations — edge cases (very young entry age, short gaps near 6 years) may produce premiums that diverge significantly from Manulife's actual rates (**likely**). The Premi-to-Dana Mapan reverse calculation iterates through bands highest-first but silently falls through to band 1 factor if no band boundary contains the result, producing a valid-looking but potentially incorrect answer for edge-case premi amounts (**confirmed**). The "Total Dana Mapan = 7x" label and computation conflate the term differently than the "800%" marketing figure that sums to 8x, creating potential customer confusion about guaranteed returns (**confirmed**).

## High-level view

The calculator solves the forward problem (Dana Mapan → Premi) by multiplying Dana Mapan × base rate × band factor × payment-mode multiplier, where base rates come from a lookup table for seven known points and a power-law regression for everything else. The inverse (Premi → Dana Mapan) iterates bands from highest to lowest, dividing premi by the composite rate until it finds a Dana Mapan that sits within the band's boundaries — a bisection that works for the common case but has a silent fallback when no band matches.

The seven embedded rate points reproduce the sample data exactly for Band 2 Tahunan scenarios. For the ~200 other age/gender/UM permutations, a power-law curve generates plausible rates — but without validation data, errors could compound with band factors and payment-mode multipliers to produce premiums that are materially wrong for customer-facing use.

Two distinct "total" figures coexist: "Total Manfaat 800%" (100% + 400% + 200% + 100%) in the benefit section, and "Total Dana Mapan 7x" (100% + 400% + 200%) in the premium results. The UI doesn't explain why one is 7x and the other is 8x, which will confuse users comparing the two cards.

## Rate generation and the interpolation model

The calculator embeds seven exact premium rates (annual, Band 2, per-unit Dana Mapan):

```
pria_45_55: 0.84796    pria_45_60: 0.66719
pria_34_55: 0.48141    pria_30_55: 0.4155
wanita_37_45: 0.95489  wanita_37_55: 0.60445  wanita_37_60: 0.51484
```

For any other combination, `generateRate(gender, um, umap)` computes:

```javascript
// Pria:   rate = 4.85 * Math.pow(gap, -0.82)
// Wanita: rate = 4.50 * Math.pow(gap, -0.78)
// clamped to [0.15, 1.5]
```

The concern is at extremes: an 18-year-old entering with UM 60 (gap = 42) produces `4.85 * 42^-0.82 ≈ 0.178`, and an 18-year-old with UM 25 (gap = 7) produces `4.85 * 7^-0.82 ≈ 0.90`. These may be reasonable or wildly off — there's no reference data to validate. For a customer-facing page, showing an interpolated premium without any "estimate" indicator risks setting incorrect expectations.

The clamp bounds (0.15 to 1.5) prevent absurd values but don't prevent wrong-but-plausible ones.

## Reverse calculation: Premi → Dana Mapan

When the user inputs a premium amount, the calculator must find the Dana Mapan that would produce that premium:

```javascript
var bandsList = [{min:500000000, mx:Infinity, f:0.88}, {min:200000000, ...f:0.925},
                 {min:100000000, ...f:1.0}, {min:50000000, ...f:1.05}];
var mult = paymentMode==='tunggal' ? tunggalFactor : paymentMultipliers[paymentMode];
for (var bi=0; bi<bandsList.length; bi++) {
  var tryDM = Math.round(premi / (rateBase * bd.f * mult));
  if (tryDM >= bd.min && tryDM <= bd.mx) { danaMapan = tryDM; break; }
}
if (danaMapan === 0) { danaMapan = Math.round(premi / (rateBase * 1.05 * mult)); }
```

The iteration goes from band 4 (highest Dana Mapan, lowest factor) to band 1 (lowest Dana Mapan, highest factor). At band boundaries — for instance, a premi that maps to Dana Mapan 99,999,999 with band-2 factor but 104,761,905 with band-1 factor — the loop may not find a match in any band, falling through to the default. The default uses band-1 factor (1.05) regardless of the resulting Dana Mapan magnitude, which could place the answer in band 3 or 4 territory without any error indication.

## The 7x vs 8x confusion

The "Total Dana Mapan (7x)" card computes `danaMapan * 7` and labels it "Rincian 7x: 100% + 400% + 200%". This represents guaranteed cash flows if the insured survives. The benefit section shows `danaMapan * 8` labeled "800% Dana Mapan" with composition "100% + 400% + 200% + 100% (perlindungan)".

The difference is the death benefit (100%), paid only if the insured dies during coverage — mutually exclusive with surviving to collect all cash flows. Presenting them side-by-side without explanation creates ambiguity. The 800% disclaimer ("*Total 800% berlaku jika tertanggung hidup hingga akhir masa pertanggungan") partially addresses this but doesn't explain the 7x card.

## Premi Tunggal factor composition

For single premium mode:

```javascript
premi = Math.round(danaMapan * rateBase * bandFactor * getTunggalFactor(...))
```

The `tunggalFactor` (ranging 4.0–4.6) was derived from sample data by dividing single premium by (danaMapan × annual rate). The sample data was Band 2 (factor 1.0), so for Band 2 the formula is correct. For other bands, the `bandFactor` is multiplied in addition — this assumes the tunggal factor is band-independent. The architecture means Band 1 single premium = Band 2 × 1.05, and Band 4 = Band 2 × 0.88. Whether Manulife's actual single premium rates scale linearly with band factor is unverified.
